# المعمارية وقرار النسخة التجريبية

## القرار

تبدأ النسخة بواجهة عربية للهاتف، وواجهة API صغيرة، ومحول ComfyUI اختياري إلى خادم GPU خاص. لا نضم نماذج التوليد أو أوزانها إلى الحزمة. يبقى دفتر Wan2.1 T2V-1.3B الموجود مسار Colab منفصلاً للتجارب اليدوية.

يقلّل هذا الفصل ازدواجية كود النماذج ويتيح تبديل workflows من دون ربط واجهة الهاتف بعائلة نموذج واحدة. لكنه لا يحل تلقائياً طوابير الإنتاج أو التراخيص أو موارد GPU.

## تدفق المهمة

1. يرسل المتصفح وصفاً نصياً محدود الطول إلى `POST /api/v1/jobs`.
2. ينسخ المحول workflow API الموثوق محلياً ويضع الوصف في عقدة محددة بالإعداد.
3. يرسل الخادم الرسم إلى ComfyUI عبر `/prompt` ويحصل على معرّف المهمة.
4. تستعلم الواجهة عن `/api/v1/jobs/{id}`، ويستعلم محول ComfyUI من سجل المهمة والطابور.
5. عند الاكتمال، تعرض الواجهة مخرجات workflow عبر مسار تنزيل وسيط يمر عبر الخادم.

المعرّفات الخارجية لا تعرّف محركاً بعينه داخل واجهة المستخدم. عقد `VideoProvider` في `saher_video/contracts.py` هي حد الفصل لإضافة محولات مستقبلية؛ لا يوجد حالياً سوى محول ComfyUI.

## حدود النسخة الحالية

حالة الواجهة والمؤشر مستمدان من ComfyUI، ولا يوجد تخزين دائم محلي أو إعادة محاولة أو إلغاء أو قائمة مهام خاصة بساهر. لا توجد مصادقة أو حماية متعددة المستخدمين أو رفع وسائط. المتصفح لا يشغّل النموذج. إعدادات الموارد والتحقق من workflow وتوافر GPU مسؤولية المشغّل. لا تحتوي الشيفرة على نموذج افتراضي قابل للتشغيل؛ إذ إن workflow يعتمد على العقد والنموذج ومسارات الملفات في تثبيت ComfyUI.

## خطة الاختبار قبل اختيار محرك

على بطاقة GPU محددة، ثبّت نسخ النظام والمكتبات والنموذج وworkflow. قِس على مجموعة prompts/صور مرجعية ثابتة: معدل نجاح التوليد، زمن أول إطار/الاكتمال، أعلى ذاكرة VRAM وRAM، حجم التنزيل والملف، عدد المهام المتوازية، جودة النتائج، وأخطاء التزامن. سجّل الدقة والمدة والإعدادات عند كل قياس. لا تخلط أرقام المؤلف مع القياسات الفعلية.

قبل التوسع، اختبر عزل طابور المهام، التحكم في حجم الملفات والمدة، حدود معدل الطلب، الإلغاء، حفظ النتائج وتنظيفها، إعادة التشغيل، المصادقة، والسجلات التي لا تسرب نصوص المستخدمين. اختبر فشل المحرك أو انقطاع الشبكة قبل تشغيل الخدمة على الإنترنت.

## أولويات التطوير

1. اختبار ربط حقيقي على جهاز GPU واحد، وضبط عقد الإدخال والمخرجات.
2. إضافة API key أو بوابة مصادقة، حصص وأحجام محدودة، وتحديد تخزين خاص.
3. توحيد آلية إلغاء المهمة وتسجيلها ومعالجة انتهاء المهل.
4. اختبار FFmpeg كمرحلة اختيارية للقصّ والترميز/المزج بعد التوليد.
5. بعد قياس النسخة الأساسية، إضافة محول لمحرك آخر فقط إذا حقق فائدة واضحة وسمحت التراخيص والموارد.
6. تأجيل تحسين الدقة وRIFE ومزامنة الشفاه والرفع إلى مراحل مستقلة؛ لا تفعلها افتراضياً قبل قياس الجودة والوقت والتراخيص.
