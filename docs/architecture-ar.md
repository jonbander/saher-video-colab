# معمارية Saher Image وقرار النسخة التجريبية

## القرار

تستخدم النسخة الحالية واجهة عربية للهاتف وواجهة API صغيرة ومحول ComfyUI. يتصل المحول بخادم GPU عبر API ويرسل workflow نص-إلى-صورة. أضفنا workflow افتراضياً لـStable Diffusion 1.5 FP16 بمقاس 512×512 وخطوات أخذ عينات بسيطة. لا تُنسخ أوزان النموذج داخل المستودع.

أرشفت مسارات Wan2.1 وComfyUI الفيديو القديمة في `archive/`. اختيار SD1.5 يخفف متطلبات الذاكرة والتنزيل مقارنة بتوليد الفيديو؛ لكنه نموذج أقدم ولا يضمن جودة صور النماذج الأحدث.

## تدفق المهمة

1. يرسل العميل prompt من 3 إلى 4000 محرف إلى `POST /api/v1/jobs`.
2. ينسخ المحول workflow API المحدد محلياً ويضع النص في العقدة `6`.
3. يرسل Saher الرسم إلى ComfyUI عبر `/prompt` ويحصل على معرّف المهمة.
4. تستعلم الواجهة عن حالة المهمة، ويستعلم المحول من طابور ComfyUI وسجلها.
5. عند النجاح، يحصل التطبيق على PNG عبر `/view` ويعرضه عبر نقطة تنزيل Saher.

لا تضيف النسخة قائمة حظر prompts خاصة بالتطبيق. تبقى القيود التقنية، وشروط النموذج، وسياسات المنصة، والقانون سارية؛ ولا يضمن Saher قبول أو إنتاج كل طلب.

## حدود النسخة الحالية

لا يوجد تسجيل دخول، أو عزل مستخدمين، أو طابور دائم، أو إلغاء مهمة، أو رفع صورة، أو إدارة موارد إنتاجية. يعتمد التطبيق على GPU وخادم ComfyUI وworkflow محلي. يعمل توليد Kaggle من خلايا notebook؛ لا يشغّل خادماً عاماً.

## الاختبار والتطوير التالي

1. اختبار أول توليد PNG على GPU Kaggle أو جهاز محلي وتسجيل نوع GPU والذاكرة والزمن.
2. إضافة اختبارات API لعرض الصور والتحقق من انتهاء المهلة وأخطاء محرك ComfyUI.
3. قبل نشر عام، إضافة مصادقة وحد معدل وحصص وتخزين آمن وتنظيف للمخرجات.
4. بعد قياس SD1.5 على العتاد المستهدف، مقارنة نموذج أحدث إذا كانت الذاكرة والوقت يسمحان، مع مراجعة الترخيص والاختبار دون افتراض أداء مقدماً.
