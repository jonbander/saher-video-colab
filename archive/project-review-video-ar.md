# نتيجة دراسة المشاريع وقرار الدمج الأولي

## القرار المختصر

أفضل دمج للنسخة الأولى هو **تركيب الميزات وليس نسخ المستودعات**: واجهة عربية هاتفية مملوكة للمشروع، وحدّ موحد للمحركات، ثم اتصال بـ ComfyUI API على خادم GPU خاص. أبقينا دفتر Wan2.1 الحالي مستقلاً كما هو. هذا يعطي نقطة بدء صغيرة قابلة للتوسعة، ويترك اختيار النموذج والموارد وشروط استخدام كل وزن منفصلة عن واجهة المستخدم.

هذه توصية للبدء لا إثبات تفوق أداء. لم نقم بقياس جودة أو زمن أو VRAM لأي توليد في هذا التغيير.

## ما بُني في المستودع

أضيفت صفحة ويب عربية متجاوبة، ونقطة API لإنشاء المهمة واستعلامها وإرجاع ملفات output، وواجهة موحدة للمحركات، ومحول ComfyUI يعتمد على workflow API يحدده المشغّل. أضيفت اختبارات محاكاة لا تحتاج GPU، ودليل بدء سريع، ووثائق المعمارية والترخيص.

لا يتضمن المشروع ملفات أوزان، ولا workflow جاهزاً، ولا auth أو رفع صور أو database أو queue دائم. لا يعلن عن دعم جميع قدرات النماذج؛ المرحلة الحالية نص إلى workflow مجهز سلفاً فقط. والدفتر القديم لم يُشغّل أو يختبر فعلياً ضمن هذا العمل.

## الخطوة الصحيحة قبل ادعاء «أفضل أداء»

اختر جهاز GPU واحداً وworkflow ثابتاً، ثم قارن على prompts متطابقة: زمن المهمة، أعلى VRAM/RAM، معدل نجاح التشغيل، حجم المخرجات، التزامن، ونتائج الجودة. لا نقارن مواصفات نماذج منشورة بأداء فعلي على استضافتنا؛ ونختار بعد ذلك نموذجاً واحداً فقط للنسخة التجريبية. اقرأ [مصفوفة التراخيص الأولية](licenses-ar.md) قبل تنزيل أي وزن.
